# Bug Report: 2026-05-09 串口模式解析错误

## 发现日期
2026-05-09

## 发现人
视觉组

## 相关文件
- `io/gimbal/gimbal.cpp` 第 252-255 行（修复前）
- `io/gimbal/gimbal.hpp` — ReceiveFrame 结构体定义
- `MiniPC_Protocol_Doc.md` — 协议文档

## Bug 1：gimbal_req_mode 比较使用了十进制而非十六进制

### 问题
协议定义 `gimbal_req_mode` 使用十六进制值：
```
0x10 = 无请求
0x11 = 自瞄
0x12 = 小符
0x13 = 大符
```

但 `gimbal.cpp` 第 252-255 行使用了十进制比较：
```cpp
// 修复前（错误）
if (rx.mode == 11) mode_ = GimbalMode::AUTO_AIM;          // 11 ≠ 0x11(17)
else if (rx.mode == 12) mode_ = GimbalMode::SMALL_BUFF;   // 12 ≠ 0x12(18)
else if (rx.mode == 13) mode_ = GimbalMode::BIG_BUFF;     // 13 ≠ 0x13(19)
else mode_ = GimbalMode::IDLE;
```

EC 发送 `0x11`（十进制 17），与 `11` 永远不匹配，导致始终落入 `IDLE`。

### 修复
```cpp
// 修复后（正确）
if (rx.mode == 0x11) mode_ = GimbalMode::AUTO_AIM;
else if (rx.mode == 0x12) mode_ = GimbalMode::SMALL_BUFF;
else if (rx.mode == 0x13) mode_ = GimbalMode::BIG_BUFF;
else mode_ = GimbalMode::IDLE;
```

### 影响
- 视觉程序无法从串口接收自瞄模式请求
- 摄像头不会启动采集
- 之前能工作是因为使用了硬编码 `mode = io::GimbalMode::AUTO_AIM;`（绕过串口）

## Bug 2：EC 固件未填充 gimbal_req_mode 字段

### 问题
串口数据正常到达（GD 帧 CRC 校验通过），但 `rx.mode` 始终为 `0x00`（非协议定义的有效值）。

GD 帧第 36 字节（`gimbal_req_mode`）未按协议写入：
- 当前 EC 发送：`0x00`
- 期望 EC 发送：`0x11`（自瞄模式）

### 验证日志
```
[Gimbal] GD frame rx.mode=0x00 (dec:0)   ← 3 帧全部为 0x00
```

### 建议
电控侧将固件中 `_NUC_UART_INFO_2_0_t.gimbal_req_mode` 按遥控器模式正确赋值：
- 切换自瞄时 → `0x11`
- 无请求时 → `0x10`
- 大符 → `0x13`
- 小符 → `0x12`

## 临时 Workaround
在 EC 固件修复前，`QYG_sentry_debug.cpp` 使用强制模式：
```cpp
mode = io::GimbalMode::AUTO_AIM; // 临时强制自瞄
//mode = gimbal.mode();           // 等 EC 修复后启用
```
