## 1. `shared_ptr` 与对象的关系

### 核心认识

`shared_ptr` 是**指向对象的指针**，不是对象本身。

```cpp
auto aim2nav = std::make_shared<io::Aim2Nav>();
//  ↑                       ↑
//  这是指针变量             这个函数返回 shared_ptr
```

### 拆解这行代码

```
auto aim2nav = std::make_shared<io::Aim2Nav>();
│    │               │
│    │               └── "make_shared" = "创建一个共享指针"
│    │                   永远返回 shared_ptr<T>，不返回 T
│    └── 变量名，类型由 auto 推导
└── 自动推导为 shared_ptr<io::Aim2Nav>
```

---

## 2. 对象在栈上 vs 堆上 vs 智能指针

| 写法 | aim2nav 是什么 | 对象在哪 | 生命周期 |
|------|:-------------:|:------:|------|
| `Aim2Nav aim2nav;` | **对象本身** | 栈 | 离开作用域自动析构 |
| `Aim2Nav* aim2nav = new Aim2Nav();` | **裸指针** | 堆 | 必须手动 `delete` |
| `auto aim2nav = make_shared<Aim2Nav>();` | **智能指针** | 堆 | 最后一个持有者消失自动释放 |

### 图解

```
栈（函数局部变量）                   堆（动态分配的内存）
┌──────────────────┐             ┌────────────────────────┐
│ aim2nav          │             │  Aim2Nav 实例           │
│ (shared_ptr)     │ ──指向──→   │  ├ latest_state_       │
│ 地址: 0x7f...    │             │  ├ data_buffer_        │
│ 引用计数: 2      │             │  ├ mutex_              │
└──────────────────┘             │  └ node_               │
                                 └────────────────────────┘
```

## 3. 如何一眼识别 `shared_ptr`

### 证据一：`make_shared` 函数名

```cpp
std::make_shared<T>()   // 名字就叫"创建共享指针"，返回 shared_ptr<T>
```

### 证据二：`auto` 类型推导

```cpp
auto x = std::make_shared<int>();
// x 的类型 = shared_ptr<int>，不是 int
```

### 证据三：函数参数类型声明

```cpp
// gimbal.hpp 中的声明
void set_aim2nav(std::shared_ptr<Aim2Nav> aim2nav) { aim2nav_ = aim2nav; }
//               ↑ 参数明确要求 shared_ptr<Aim2Nav>

// 调用处
gimbal.set_aim2nav(aim2nav);  
// 如果 aim2nav 不是 shared_ptr，编译器会直接报错
```

## 4. 私有成员不能直接访问

```cpp
class Aim2Nav {
private:
    GimbalState latest_state_;   // 私有成员变量
    std::mutex mutex_;            // 私有成员变量
public:
    GimbalState get_latest_state();  // 公有接口
};

// 外部代码
auto aim2nav = std::make_shared<Aim2Nav>();

aim2nav->latest_state_;       // ❌ 编译报错！不允许直接访问私有成员
aim2nav->get_latest_state();  // ✅ 正确！通过公有函数间接访问
```

**这是 C++ 封装的核心**：外部只能通过类提供的公有接口操作对象，不能直接动内部数据。

---

## 5. 为什么用 shared_ptr？

以 `Aim2Nav` 为例，它被**多方持有**：

| 持有者 | 用途 |
|--------|------|
| `QYG_sentry_debug.cpp` 的 `main()` 中的 `aim2nav` | 创建者，保持引用 |
| `gimbal` 对象内部的 `aim2nav_` | 收到 EC 数据时调用 `aim2nav_->publish(state)` |

多个持有者共享同一个对象，`shared_ptr` 通过**引用计数**自动管理：最后一个持有者消失时自动释放内存，无需手动 `delete`。

---

## 6. 抽象理解

| 概念 | 类比 |
|------|------|
| `shared_ptr<Aim2Nav>` | 遥控器 |
| `Aim2Nav` 对象 | 电视机 |
| `latest_state_`（私有成员） | 电视内部的电路板 |
| `get_latest_state()`（公有函数） | 遥控器上的按钮 |
| `make_shared<T>()` | 买一台新电视并给你遥控器 |

> 你有遥控器（shared_ptr），靠按按钮（公有函数）控制电视（对象），但不能伸手进电视里拨电路板（私有变量）。
