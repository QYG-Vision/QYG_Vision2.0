# 5月29日自瞄调试知识总结

**日期**：2026-05-29

---

## 学习内容概述

本次总结记录 `QYG_sentry_debug.cpp` 中 `target_queue`、`planner` 线程和多个 `gimbal.send()` 分支之间的关系。重点理解之前 pitch 接管被打断的 bug：无目标或队列空隙时反复发送 `control=false / yaw=0 / pitch=0`，导致下位机认为视觉接管中断。

---

## 核心知识点总结

### 1. `target_queue` 不是图像队列

`target_queue` 里保存的是跟踪后的目标结果，不是相机图像：

```cpp
tools::ThreadSafeQueue<std::optional<auto_aim::Target>, true> target_queue(1);
```

完整链路如下：

```text
detect_thread
  camera.read(img)
  detector.push(img, t)

main thread
  detector.debug_pop()
  tracker.track(armors, t)
  target_queue.push(Target 或 nullopt)

plan_thread
  target_queue.pop()
  planner.plan(...)
  gimbal.send(...)
```

所以 `target_queue` 的 empty 不是“相机没有图像”，而是“plan 线程暂时没有拿到新的目标结果”。

### 2. `target_queue` 的三种状态

| 状态 | 含义 | 应该怎么发云台 |
|------|------|----------------|
| 队列里有 `Target` | 这一帧有目标 | `control=true`，发 planner 算出的 `yaw/pitch` |
| 队列里有 `nullopt` | 这一帧处理完了，但明确没目标 | `control=true`，保持上一帧 `yaw/pitch` |
| 队列暂时 empty | plan 线程比 main 线程更快，新结果还没 push 进来 | `control=true`，保持上一帧 `yaw/pitch` |

第三种状态是多线程节奏造成的短暂空隙。它不是检测器没工作，也不是相机断流。

### 3. `PLANNER / HOLD_NO_TARGET` 分支

条件：

```cpp
mode == io::GimbalMode::AUTO_AIM && !target_queue.empty()
```

这个分支表示队列里有新结果。新结果可能是真目标，也可能是 `nullopt`。

处理逻辑：

```text
有 Target：
  planner.plan(target, bullet_speed)
  使用 planner 输出的 yaw/pitch

有 nullopt 或 planner 不控制：
  不再发 0
  保持 last_yaw / last_pitch
```

关键点是最后保持视觉接管：

```cpp
tx_control = true;
```

这样即使这一帧没有目标，下位机仍然知道视觉还在接管云台。

### 4. `HOLD_QUEUE_EMPTY` 分支

条件：

```cpp
mode == io::GimbalMode::AUTO_AIM
```

但前面的 `!target_queue.empty()` 不成立，说明现在处于 AUTO_AIM 模式，但队列暂时空。

此时不调用 planner，只做保活：

```cpp
gimbal.send(
  true, false, tx_yaw, tx_pitch,
  cmd_vel.linear.x, cmd_vel.linear.y, cmd_vel.angular.z);
```

其中：

```text
control = true
fire = false
yaw/pitch = last_yaw / last_pitch
```

这个分支的作用是填补多线程之间的空隙，避免视觉控制在两帧之间被下位机误判为中断。

### 5. 之前 pitch 接管 bug 的根因

原来的问题不是云台不能被视觉控制，而是无目标或队列空隙时反复发送：

```cpp
gimbal.send(false, false, 0, 0, ...);
```

这会让下位机收到：

```text
control=false
yaw=0
pitch=0
```

下位机因此认为视觉不再接管云台，pitch 控制被打断。表现出来就是：有目标时视觉抢回控制，没目标或队列空时又释放控制，pitch 接管不连续。

修正后的原则：

```text
AUTO_AIM 模式下：
  有目标：control=true，发 planner yaw/pitch
  明确无目标：control=true，保持 last_yaw/last_pitch
  队列暂时空：control=true，保持 last_yaw/last_pitch

非 AUTO_AIM 或纯 PnP 图像测试：
  control=false
```

## 实际项目应用

当前 `QYG_sentry_debug.cpp` 中几个 `gimbal.send()` 的角色：

| 分支 | 作用 |
|------|------|
| `PNP_IMAGE_ONLY_TEST` | 纯图像/PnP 测试，不让 planner 控制云台 |
| `PLANNER` | 有目标时使用 planner 输出控制云台 |
| `HOLD_NO_TARGET` | 本帧明确没目标，但继续视觉接管并保持上一帧角度 |
| `HOLD_QUEUE_EMPTY` | 队列短暂为空，继续视觉接管并保持上一帧角度 |
| 程序退出 | 发送全停，释放视觉控制 |

调试时要区分：

```text
nullopt：这一帧明确没目标
empty：这一刻还没有新结果
```

它们都不能在 AUTO_AIM 模式下随便发 `control=false`，否则会复现 pitch 接管中断问题。

---

## 学习收获

1. 多线程程序中的“队列空”不等于“没有目标”，也不等于“没有图像”。
2. 自瞄控制链路里，`control` 比 `yaw/pitch` 的数值更基础；`control=false` 会改变下位机是否接受视觉接管。
3. 无目标分支和队列空分支都要保持 `control=true + hold yaw/pitch`，这样云台控制才连续。
4. 纯 PnP 测试和正常自瞄控制要分层隔离，不能混在同一个结论里分析。
