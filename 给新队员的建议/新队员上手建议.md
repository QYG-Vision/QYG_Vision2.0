# 新队员上手建议

这份文档写给刚加入视觉组、准备基于 `qlf-clean` 开发的队员。

请先记住最重要的一条：

```text
qlf-clean 是模板分支，不是你的个人开发分支。
不要直接在 qlf-clean 上写代码。
不要把你的个人改动直接合并到 qlf-clean。
不要污染 qlf-clean。
```

`qlf-clean` 的作用是提供一份能编译、能运行、带必要模型资源的基线工程。你应该基于它创建自己的并列分支，然后在自己的分支上开发、实验、提交。

## 1. 克隆仓库

```bash
git clone git@github.com:QYG-Vision/QYG_Vision2.0.git
cd QYG_Vision2.0
```

如果你没有配置 GitHub SSH key，可以先找负责人帮你配置，或者临时使用 HTTPS 地址克隆。

## 2. 切到模板分支

```bash
git checkout qlf-clean
git pull --rebase origin qlf-clean
```

`qlf-clean` 是当前推荐的模板分支。它不是你的工作分支，只用来作为创建个人分支的起点。

## 3. 下载模型资源

模型文件由 Git LFS 管理。第一次使用前执行：

```bash
git lfs install
git lfs pull
```

如果系统没有安装 Git LFS，先安装：

```bash
sudo apt install git-lfs
```

模型资源由模板分支统一维护。平时开发代码时，不要修改、替换或提交模型文件。只有负责人明确要求更新模型时，才处理模型文件。

## 4. 创建自己的并列分支

请用自己的姓名拼音缩写创建个人分支：

```bash
git checkout -b <姓名拼音缩写>
```

例如：

```bash
git checkout -b zjh
git checkout -b wlc
git checkout -b ljx
```

如果你同时做多个方向，可以在缩写后加任务名：

```bash
git checkout -b zjh-auto-aim
git checkout -b zjh-nav-bridge
```

这些分支和 `qlf-clean` 是并列关系。你的提交应该进入你自己的分支，而不是进入 `qlf-clean`。

## 5. 日常开发前同步模板

每次开始开发前，先更新模板分支，再把自己的分支同步到最新模板：

```bash
git checkout qlf-clean
git pull --rebase origin qlf-clean
git checkout <姓名拼音缩写>
git rebase qlf-clean
```

如果 rebase 发生冲突，先停下来解决冲突。不要用强制覆盖的方式处理，也不要把别人的代码随便删掉。

## 6. 提交自己的代码

先查看自己改了什么：

```bash
git status
```

不要无脑使用：

```bash
git add .
```

推荐按文件添加：

```bash
git add src/xxx.cpp
git add tasks/auto_aim/xxx.cpp
git add docs/xxx.md
```

提交前检查暂存区：

```bash
git diff --cached --stat
```

确认没有混入这些内容：

- `build/`
- `Build/`
- `install/`
- `logs/`
- `records/`
- `.cache/`
- 临时视频
- 缓存文件
- 没有被要求更新的模型文件

确认无误后，提交到你自己的分支：

```bash
git commit -m "简短说明本次改动"
git push origin <姓名拼音缩写>
```

## 7. 关于合并

默认情况下，不要把你的个人分支直接合并到 `qlf-clean`。

如果你的功能已经验证完成，需要合并回模板分支，请先和负责人确认。确认之后再由负责人或指定的人进行合并。

合并前至少要满足：

- 相关目标能编译。
- 程序能按预期运行。
- 没有提交生成物、缓存、大视频、日志。
- 没有误提交模型文件。
- 文档、测试和代码改动分组清楚。
- 你能说清楚这次改动解决了什么问题。

## 8. 一句话总结

```text
先从 qlf-clean 拉自己的分支。
只在自己的分支上开发。
不要直接动 qlf-clean。
不要把未经确认的改动合并回 qlf-clean。
```
